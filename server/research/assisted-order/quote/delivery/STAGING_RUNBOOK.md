# Isolated Early Access quote rehearsal

This rehearsal is limited to Render service `srv-d9h4f4m7r5hc73ctjng0`, its `https://xenios-research-staging.onrender.com` origin, and Supabase project `tetynodzrtmdbuzgboro`. It is one approved synthetic quote and one authorized notice to Samuel’s work inbox. It does not configure production.

1. In the [isolated Supabase project](https://supabase.com/dashboard/project/tetynodzrtmdbuzgboro), open **Connect → Session pooler** and take the exact host from the project. The database administrator assigns a new password to the already-created `ea_quote_stage_login` using the masked `psql` command `\password ea_quote_stage_login`, then enables that role with `ALTER ROLE ea_quote_stage_login LOGIN;`. Preserve its non-inheriting, non-administrative membership with `SET` permission on `ea_quote_stage_runtime`. Do not use the project administrator’s password for the app.
2. In the [isolated Render service](https://dashboard.render.com/web/srv-d9h4f4m7r5hc73ctjng0) under **Environment**, set `EA_STAGE_QUOTE_DATABASE_URL` to the session-pooler connection using host `aws-1-us-west-2.pooler.supabase.com`, username `ea_quote_stage_login.tetynodzrtmdbuzgboro`, port 5432, database `postgres` and the newly assigned password. Percent-encode the password and omit driver options; the app uses the Supabase Root 2021 CA and verifies the pooler hostname. Check that the existing `ADMIN_EMAIL` identifies the authorized issuer, and check presence of `RESEND_API_KEY`. Report only pass/fail, never values or the full connection string.
3. The staff-only `GET /api/staff/early-access/private-quotes/staging-readiness` checks the actual running connection by entering a transaction, assuming the restricted role and confirming the session login. It returns only the restricted-connection and mail-key-presence booleans. A 200 is connection evidence; it does not claim the sender or recipient received mail.
4. Record the privacy decision and approved retention/purge configuration in KAN-149 before using real contact information. After the original browser makes the selected, single-line synthetic request under the current policy, authorize the synthetic offer and set the server-only `EA_STAGE_QUOTE_FIXTURE`. It carries the persisted `xriId`, `ownerHash`, `attemptHash`, `customerRef`, the existing `issuerId` and controlled `recipientId` (verified Supabase Auth UUIDs), the reviewed `productId` and `variantId`, an `approvalEvidenceId`, approved synthetic `unitPriceCents` and UTC ISO `validUntil` (within seven days). Use private staging configuration; do not put request identifiers or contact data in source or public tickets. The issuer must match the existing administrator guard and retain the existing request-intent pending-read authority. Set `EA_STAGE_QUOTE_TAG_KEY` to a dedicated, stable, randomly generated 32-byte hex secret. Keep `EA_STAGE_QUOTE_DELIVERY_APPROVED` off during initial portal proof.
5. With the integrated SHA deployed, the authorized issuer submits JSON `{}` to `POST /api/staff/early-access/private-quotes/issue` from the staging origin with their normal Supabase admin session. The original customer browser opens `/earlyaccess/quotes`; a fresh session must receive 401 with no quote details. The first issue never creates a mail job. After the privacy decision permits delivery and both browser checks pass, set `EA_STAGE_QUOTE_DELIVERY_APPROVED=true` on the same revision. Repeat the exact same issuance action once to release the single idempotent notice. Use the managed outbox and both inboxes to verify actual delivery and the reply. Provider acceptance alone does not prove delivery.
