# Release milestones and proof

## A0: disabled route candidate (intermediate only)

The approved source mount shows the real shell and an honest unavailable notice.
Sensitive route privacy/noindex/PWA behavior is correct. API containment precedes
body parsing. No customer data is collected and no purchase is offered.

This is NOT a useful completed Quick Order product. Do not call it live intake.

## A: live request intake

All of the following must hold for the exact candidate:
- correct canonical offers and provider/held states, with no copied catalog;
- established actor/session/standing and approved Health terms/destination;
- complete form/referral/affiliation and review/edit states;
- real canonical adapter and transaction: request, lines, declarations, replay
  receipt and existing outbox obligation saved atomically;
- same actor/key retries return the same reference after restart/response loss;
- changed-input key reuse and cross-actor access refused;
- decisive catalog/legal/price/destination currentness bound to real writers;
- authorized operator can read the complete request through the actual workflow;
- marketing/PII/cache/privacy/PWA behavior qualified on the real application;
- review, focused tests, build, appropriate database and browser proof;
- exact source/protected/schema/release authority and served-runtime checks.

Customer language: Submit request, Request received, review/quote pending.
No paid or fulfillment/clinical promise. No payment collection in this release.

## B: live purchasing

Meet A plus the selected purchase flow's actual eligibility and payment policy.
Bind accepted quote, canonical request, amount/currency and durable payment
attempt; verify independent provider/bank evidence; prevent reuse across orders;
handle replay/unknown outcomes, failed payment and applicable refunds/disputes;
advance fulfillment only with the necessary payment/provider authority.

The order-request form is not this payment system. A confirmation redirect,
typed reference or screenshot is insufficient independent payment evidence.
No charge or bank details may be invented. Any real payment smoke test needs
its own exact authorization.

## C: full-site release completion

Qualify homepage/navigation, canonical catalog/member product detail, request/
quote/payment/status, sign-in/recovery, partner/referral/admin scope, applicable
subscription management, support, notifications and errors. Publish only actual
approved assets. Resolve MC-01/D-E database/history/currentness and financial
holds relevant to included runtime. Complete mobile/desktop/zoom/accessibility,
performance, full aggregate and rollback verification.

## Release packet (one, exact and understandable)

- Candidate source/tree and actual served predecessor.
- Included capabilities and disabled exclusions.
- Accepted reviews and exact test/evidence references.
- Protected manifest disposition, inherited issues and GATE-01 choice.
- Schema predecessor census, source candidate, approved apply/adoption plan.
- Configuration/feature changes, no secret values in the packet.
- Verified deployment destination/service and actual action list.
- Backup/recovery/rollback plan, especially for irreversible data actions.
- Read-only and separately authorized write/charge smoke tests.
- Proposed final approval and observable success/failure conditions.

A user deployment goal is not proof that these preconditions have been met.
Deploy promptly once the precise release is approved and qualified; do not
re-run broad history or solicit another generic planning round.
