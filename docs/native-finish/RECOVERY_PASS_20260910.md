## Exact implementation

`createCheckoutRecoveryPass(...).runOnce(...)` joins the real durable operation,
raw canonical Supabase execution repository, canonical payment-evidence mapper
and actual executor.settleUnattended. It never uses the notification-wrapped
checkout composition. No module resolves credentials or starts a timer/route.
The existing execution client interface accepts PromiseLike SDK results; this is
a type-only compatibility change, not a changed query or row mapping.

Default disabled invocation does not call the clock, authority callback, client
factory, database or provider. Enabled calls require exact project/environment,
application SHA, approval digest, validity window, explicit four-effect scope
and member scope. A caller must supply authentic fresh verification and the
connection actually verified; echoing a desired context is not independent
verification or permission. This module does not parse approval documents or
invent a production authorization. Every database/provider operation rechecks
the supplied verified binding and refuses a change/expiry.

Permitted effect vocabulary is durable recovery metadata, canonical local
settlement, existing-payment inspection and existing-authorization cancellation.
Creation, confirmation, capture initiation, refund, webhook processing and
notifications are not delegated to the executor. Project-wide discovery refuses
mixed-member pages rather than filtering them and advancing an incomplete cursor.
Foreign pending work is refused before claim; if it appears during that race,
the acknowledged lease is adopted, execution access refused and release attempted.
Revoked authority can prevent release; that is reported as releaseFailed rather
than bypassing the gate. Database lease expiry remains the bounded fallback.

No migration was added or applied to a managed project. The prior recovery and
credit candidates remain separately subject to authorized installation. An
operational caller/scheduling and managed qualification are still outstanding.
