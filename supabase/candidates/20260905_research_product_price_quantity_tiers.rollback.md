# Quantity-tier candidate rollback

This candidate is unapplied. No rollback or production action is authorized.
Precheck must reconcile exact remote function definitions/ACLs and prerequisites;
the version ledger alone is insufficient. Preserve those definitions and the
pre-application price/audit counts as the final packet's rollback basis.

If the transaction fails, PostgreSQL rolls back the whole candidate. If a later
application succeeds but runtime smoke fails, disable the new write entry point
through a separately reviewed revoke and roll back application runtime to its
approved exact SHA. Preserve the column, immutable trigger and every price row.
Never remove tiers or revert the economic trigger after tiered history exists:
that would strip an economic fact from an immutable price version. The earlier
runtime may not understand tier prices, so approved price activation must remain
a separate later gate with its own deactivation/compensating-version plan.

Any schema reversal before any tier write would require verified zero tier rows,
zero tier audit events, no active writers and exact precheck definitions/ACLs.
No speculative destructive reversal SQL is supplied. No migration-history repair,
old migration replay, product publication, price activation or supplier mutation
is part of this candidate.
