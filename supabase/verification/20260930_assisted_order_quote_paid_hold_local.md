# HL-12 temporary paid hold: disposable local proof

This is an interim fail-closed control. It prevents a free-text payment-verification ID from becoming `paid` before an accepted quote, observed amount/currency, authorized verifier and durable verification record are mounted. It does **not** supply those records or complete the payment path.

Candidate: `supabase/migrations/20260930193033_research_assisted_order_quote_paid_hold.sql`, created with Supabase CLI 2.51.0. The exact checksum/source SHA must be pinned after commit. No managed migration was applied.

On disposable `postgres:17-alpine`, the role bootstrap, M71 bridge, the HL-26 deterministic-conflict candidate, then this paid-hold candidate were applied with `psql -v ON_ERROR_STOP=1`. This candidate applied twice at exit 0. A synthetic payment-review request was inserted locally. `service_role` called the real `research_assisted_order_set_status` RPC with `paymentVerificationId = 'x'`; PostgreSQL returned `P0001` / `ASSISTED_ORDER_FINANCIAL_AUTHORITY_NOT_READY`, leaving the request in `payment_review` with zero new events. PostgREST v14.13 returned the same refusal in 115 ms; the mounted application's repository maps the detail to HTTP 409. A locally simulated historical paid label could not transition to either `supplier_processing` or `cancelled` with only their prior free-text evidence fields. The trigger function has no EXECUTE grant to `anon` or `service_role`; it executes only as a table trigger.

The application also rejects paid with a nonblank typed ID, rejects whitespace, and hides the paid option in the existing operator form. Focused server/client tests and typecheck are recorded with the source checkpoint. This candidate is not a substitute for the full HL-12 quote/payment migration and a reviewer must not mark payment integrity complete from these denials alone. The local database, API container and private Docker network were stopped and removed. No hosted state, customer record, real email or money was touched.
