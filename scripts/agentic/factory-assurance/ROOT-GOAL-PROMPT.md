Use actual available authenticated workers, not invented seats. Reserve review capacity. Start with small independent scopes, and expand concurrency only as host resources and ownership permit.

## Learning contract

Use Lauren Tan's published engineering principles as reference material: improve architecture and executable verification before adding orchestration; preserve durable lessons selectively; measure a specific hypothesis against a fixed workload.

For each improvement, record: observed incident, evidence, scope, suspected/confirmed cause, prevention, regression case, baseline result, candidate result, reviewer, promotion decision and rollback. Prefer architecture/types/lint/behavioral tests over repeated prose instructions when they can enforce the rule.

Do not call persistent notes model training. Do not measure success using tokens or code volume. Do not allow a candidate to edit its expected answers, erase a critical case, reuse related incidents across development/holdout, or invent better aggregate scores.

A pstack pilot is optional. If useful, inspect and pin its source/version, run it on one isolated seat, preserve the current project rules and compare the same bounded workload. Do not blanket-install it across active sessions or assume Claude-specific commands work in Codex or OpenRig.
